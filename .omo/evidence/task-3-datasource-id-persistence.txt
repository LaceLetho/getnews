# Task 3: Persist datasource_id on newly-collected raw intelligence items

## Files Modified

### 1. `crypto_news_analyzer/domain/models.py` (RawIntelligenceItem)

**Added `datasource_id` field:**
- Line ~737: `datasource_id: Optional[str] = None` — nullable field on dataclass
- `create()` factory: `datasource_id` parameter added (default None), passed to cls() constructor
- `to_dict()`: `"datasource_id": self.datasource_id` included in serialized dict
- `from_dict()`: `datasource_id=data.get("datasource_id")` picks up from DB rows (absent key → None, backward compat)

**Backward compatibility preserved:**
- Default `None` means existing code creating items without datasource_id continues to work
- `from_dict()` uses `.get()` so legacy rows without the key return `None`
- Source type/source ID/external ID fields unchanged

### 2. `crypto_news_analyzer/intelligence/pipeline.py`

**`_crawler_config()` (line ~129):**
- Added `payload["datasource_id"] = datasource.id` — passes datasource ID through config to crawlers for awareness

**`_run_source()` (line ~73):**
- After `items = list(crawler.crawl(config_payload) or [])`, adds loop:
  ```python
  for item in items:
      if item.datasource_id is None:
          item.datasource_id = datasource.id
  ```
- Sets datasource_id on every item produced by a DB DataSource
- `if item.datasource_id is None` guard prevents overwriting if crawler already set it
- Items created without DB datasource context (datasource_id remains None) handled correctly

**`_serialize_raw_intelligence_item_row()` keys list:**
