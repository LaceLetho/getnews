6. MINOR OBSERVATIONS (non-blocking)
======================================================================

A. Validation-before-lock race in set_topic_datasources/add_topic_datasources:
   datasource validation occurs before lock acquisition. A datasource
   could be deleted by another thread between validation and lock.
   Mitigated by DB-level FOREIGN KEY ON DELETE RESTRICT constraint.
   Probability: extremely low. Acceptable for current usage patterns.

B. No SQLite-specific migration SQL file (only PostgreSQL 011.sql exists).
   The Python-level initialize_intelligence_tables handles both backends
   correctly via IF NOT EXISTS / PRAGMA checks.

C. set_topic_datasources is not truly atomic in the ACID sense:
   validation outside the lock + DELETE/INSERT inside the lock means
   validation can be stale. The test "atomic_no_partial_update" validates
   against invalid IDs but not against race conditions. For production
   correctness, consider moving validation inside the lock or using
   SAVEPOINT/transaction-level validation.
