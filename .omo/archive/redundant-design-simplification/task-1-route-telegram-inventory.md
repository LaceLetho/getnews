## 4. `is_active` REDUNDANCY ANALYSIS

### 4.1 Schema (storage/intelligence_schema.py:46-54)
```sql
CREATE TABLE IF NOT EXISTS intelligence_topics (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,       -- REDUNDANT field
    lifecycle_status TEXT NOT NULL DEFAULT 'active',  -- CANONICAL field
    ...
);
CREATE INDEX ON intelligence_topics (is_active, updated_at DESC);  -- line 127
```
Both `is_active` and `lifecycle_status` are independently persisted columns.

### 4.2 Domain Model Derivation (domain/models.py:852-878)
```python
@dataclass
class IntelligenceTopic:
    id: str
    name: str
    is_active: bool = True                                         # line 856
    lifecycle_status: str = TopicLifecycleStatus.ACTIVE.value      # line 857
    ...

    def __post_init__(self):
        ...
        self.is_active = bool(self.is_active)
        if self.lifecycle_status in {
            TopicLifecycleStatus.DRAFT.value,
            TopicLifecycleStatus.PAUSED.value,     # line 873
            TopicLifecycleStatus.ARCHIVED.value,
        }:
            self.is_active = False                 # line 876 -- DERIVED
        elif self.lifecycle_status == TopicLifecycleStatus.ACTIVE.value:
            self.is_active = True                  # line 878 -- DERIVED
```
`is_active` is **always derivable** from `lifecycle_status`:
- `active` → `is_active = True`
- `draft` / `paused` / `archived` → `is_active = False`

### 4.3 TopicLifecycleStatus Enum (domain/models.py:67-71)
```python
class TopicLifecycleStatus(str, Enum):
    DRAFT = "draft"
    ACTIVE = "active"
    PAUSED = "paused"
    ARCHIVED = "archived"
```
The `PAUSED` value (`"paused"`) is the key redundancy indicator — when a topic is paused, `is_active` MUST be `False`. The database stores both values, but only `lifecycle_status` is authoritative.

### 4.5 Redundancy Mapping

```
lifecycle_status == "active"   ⇔  is_active == True
lifecycle_status == "draft"    ⇔  is_active == False
lifecycle_status == "paused"   ⇔  is_active == False
lifecycle_status == "archived" ⇔  is_active == False
```

The `is_active` column is a **materialized denormalization** that can be replaced by a computed property or SQL expression:

```sql
-- Current query filter (data_manager.py:2726)
WHERE is_active = ?

-- Equivalent query using canonical field only
WHERE lifecycle_status = 'active'
```

The existing index `(is_active, updated_at DESC)` at `intelligence_schema.py:127` would need to become `(lifecycle_status, updated_at DESC)` for equivalent performance.

### 4.6 Persistence Path

`upsert_intelligence_topic` (`data_manager.py:2675-2703`) persists both columns:
```python
columns = ["id", "name", "is_active", "lifecycle_status", "created_at", "updated_at"]
```
Values come from `topic.to_dict()` which includes `is_active` after `__post_init__` derivation.
